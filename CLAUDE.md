# Bookwright

Personal book-writing PWA (React + Vite + TS). Book data lives in IndexedDB and syncs to a private GitHub data repo as one JSON file per item.

## Editing the Globe (worlds)

The user wants worlds built and edited mostly by Claude. A world is `seed + params + ops` (see `src/world/ops.ts` for the op language); everything else is generated deterministically.

- Get the world JSON: the user exports it from the Globe panel ("Edit with Claude" > Export JSON), or it is `worlds/<id>.json` in the data repo when sync is on.
- Understand it first: `node scripts/world.ts describe <file>`, `query <file> <lat> <lon>`, `preview <file> out.png [--region N,S,W,E]` (read the PNG).
- Edit `ops` (or `node scripts/world.ts add <file> '<op json>'`), keep ids stable, give features names.
- Always `node scripts/world.ts validate <file>` and fix errors; read warnings; preview the area you changed.
- `node scripts/world.ts brief <file>` prints the full op reference.

## Old procedural Globe roadmap (approved plan; all 6 phases done; hidden on request, code kept. The Globe tab now is a view of the flat map, see New Map Test)

Goal: a 3D, high-def, zoomable globe that is the book's world map, built and edited mostly by Claude (the user is not artsy, but names features), tied into wiki, timeline and scenes.

- Done, Phase 1 (`7e67600`): procedural planet (`terrain.ts`, `noise.ts`), cube-sphere LOD tiles in workers (`tile.ts`, `terrain.worker.ts`), camera/rendering (`globe.ts`), page (`WorldPage.tsx`).
- Done, Phase 2 (`9359f2f`): op language (`ops.ts`, `geo.ts`), describe/query/validate/brief (`describe.ts`), CLI `scripts/world.ts`, rivers drawn as lines, panel feature list + import/export + Copy AI brief.
- Done, Phase 3: layers (`layers.ts`: `world.layers[]` of `{id,name,kind,color?,opacity?,hidden?,items}`, items have one of `at`/`path`/`area` plus `props`, `note`, `wikiId`; validated in `validate`, listed in `describe`/`brief`, drawn by CLI `preview`). Globe draws them as draped points/lines/fills (`buildOverlays`), hover highlights the nearest feature (`pickFeature`), click opens a popup (rename, note, stats, wiki link/create). Panel has layer eye/colour/opacity. Not yet: CLI command to add layer items (edit the JSON).
- Done, Phase 4 (reworked): flat map view. `flat.ts` is pure: projections (equirect/Mercator/Robinson) with a pan/zoom `View` (`makeProj(name, w, h, view)`), `detailOf` (extra noise octaves when zoomed in), and a raster painter with six basemaps (`MAP_STYLES`: atlas parchment, terrain colours, elevation tint, grey relief, dark, political) plus contours. `FlatMap.tsx` owns the canvas: drag/wheel/dbl-click/pinch/keys move the view, a cached whole-world raster is rescaled instantly, then the visible part is resampled sharp after the view settles (`CAP` px per raster). `flatDraw.ts` draws rivers/layers in screen space and places labels greedily by priority (regions, features, big settlements first), skipping any that would overlap a label or a dot. The flat map draws the derived layers too (story pins, route, party, ruler). PNG export saves the current view. Not yet: CLI `--proj`, antimeridian-straddling polygon fills, wrap-around panning.
- Done, Phase 5: `WikiEntry.place {worldId,lat,lon}`; wiki location pages have "Place it on the globe" (opens `/globe?pick=<id>`, next click sets the place) and a "Show on globe" chip (`/globe?w=&lat=&lon=`). Placed entries appear on the globe as a derived read-only "Story places" layer (id `story`, built in `WorldPage`, never saved), whose popup lists the timeline events and scenes set there. Creating a wiki page from a feature popup sets its place.
  Also: `story.ts` (pure: `arc`, `legs` with travel time at a km/day speed, `partyAt`). Globe page "Story" section: party route (great-circle legs between party events whose location entry is placed; legs needing more travel days than the story gives are flagged) and a time slider (item `from`/`to` dates on layers, `activeAt`; the party marker moves along the route by date). Ruler button measures distance (km and days at the chosen speed). Derived layers (`story`, `route`, `party`, `measure`, set `DERIVED` in `WorldPage`) are built per render and never saved. Wiki location pages show a lazy `MiniGlobe`.
  3D camera: `Globe.orbit` (toolbar toggle: plain drag rotates around the focus point; also right-drag, Q/E/W/S), pitch is free from ~0.15 radii out, double-click flies in, popup "Zoom to" frames any feature at 55° pitch (`zoomTo` in `WorldPage`, `flyTo(lat, lon, dist, tilt)`).
  Not yet: scene locations as their own pins (they show in the Story places popup), mini-globe scroll-zoom steals page scroll, measure along terrain (it is great-circle only).
- Done, Phase 6: `mergeWorld` in `merge.ts` three-way merges `worlds/*.json` per op, layer and layer item (fields I changed win, edits beat deletes, base fetched by sha, falls back to two-way). `lightMode()` in `globe.ts` (coarse pointer or narrow screen, and the mini-globe) caps tiles at a third, 2 workers, pixel ratio 1.5, coarser LOD; the flat map renders at 900 px instead of 1400. The old image maps (`MapView.tsx`) are kept on purpose: they are for hand-drawn or pasted images with pins, which the procedural globe doesn't replace; there is no converter.
- Done, terrain pass (stylised on purpose: mountains, rivers and trees are drawn bigger than life so the map is recognisable, not a satellite image):
  - `terrains.ts` is the registry: one entry per ground type (colours, `decor` props, flat-map `glyph`, optional height `shape`, `paint: true` = only paintable). `terrain.ts` classifies land with a Whittaker climate grid (sharpened borders, noise mosaics) plus overrides (beach, swamp, alpine, glacier, rock, snow); `planet.terrain(...)` returns `{id, w}` (empty id on water).
  - Ops `terrain` (circle), `zone` (polygon) and `spires` paint or raise things in the 'paint' stage; terrains with a `shape` (ripple/terrace/jag) also reshape height, damped by relief `calm`. `describe.ts` validates ids and `brief` lists every terrain.
  - Props (`props.ts`, placed in `tile.ts`): instanced low-poly trees, tufts, crystals, mushrooms on three fixed face-coordinate lattices (`TIERS`) with level windows, so every LOD agrees on where each one stands. Skipped in light mode. Sizes are oversized per tier `scale`.
  - Rivers are screen-space ribbons in `globe.ts` (km half-width, min pixels, fade when very wide); `pathDist` in `geo.ts` is chunked (bounding caps per 12 segments), which keeps tile builds fast.
  - Labels: `labels.ts` (pure: collect names, greedy non-overlapping placement) is shared by the flat map and a 2D canvas overlay on the 3D globe ("Names on the map" toggles both). Flat-map terrain symbols come from `glyphs.ts` (map-anchored jittered grid, cached per planet).
  - Demo world: `examples/terrain-showcase.json` (import via Globe panel > Import JSON). Add a showcase region when adding a terrain.
  - Exaggeration: `exag = (2 + 22 * zt ** 2.5) * relief`, so height pops from orbit and fades to true scale at the ground.
- Done, settlements and structures + natural placement (**switched off on request, code kept**: `siteFlag.on` in `sites.ts` is false, so `siteOf` returns undefined; nothing builds 3D settlements or draws site icons, the `structures` layer kind is hidden from the add-layer menu and the brief, and cities are plain markers again. Set `siteFlag.on = true` to bring it all back; the tests flip it on; the demo's `structures` layer is `hidden`. Natural terrain placement, `terrainIssues`, `fit terrain` stay active):
  - A layer item with `props.type` in `SITE_TYPES` (`sites.ts`) is a real place: hamlet..megacity (by `props.population`, footprint radius = 0.12 km * sqrt(pop/500), capped 6 km), port, farm, manor, castle, fort, tower, temple, monastery, mine, windmill, lighthouse, ruins, camp, bridge. Layer kind `structures` (any geometry) plus the old `cities`. Building style follows the terrain (`styleFor` + palettes; cold climates override timber/tropical; `props.style` forces one).
  - Pure pipeline, all in `src/world/`: `layout.ts` (`layoutSite`: seeded streets, walls, fields, harbour, landmarks in local metres; bridges chain units across the river) -> `buildings.ts` (40 low-poly unit meshes, `fix` 0 wall tint / 2 roof tint / 1 fixed) -> `settle.ts` (`buildSite`: ground probe `groundAt`, instance buffers of 16 floats, terrain-coloured decal grid, bridge snapped to the nearest river via `riverNear`). The worker answers `{item}` messages with `buildSite`; `globe.ts` (`syncSites`/`updateSites`/`receiveSite`) builds a site within 36 footprint radii of the camera, drops it past 60, hides its map marker (`hide` attribute) within 20, and `settleMat` boosts size with distance so houses stay visible. Tiles take a `clear` list so no trees grow inside a settlement (changing a site's place redoes the tiles). Derived layers (`DERIVED_LAYERS`) never become settlements.
  - Flat map: `siteGlyphs.ts` draws one icon per type (settlements grow with tier) in `flatDraw.ts`.
  - Natural placement is enforced, not just advised: `terrain` ops are ellipses (`aspect`, `angle`, defaults from the id) with three-scale wobble; `zone` outlines get a third noise scale; painted rims break into patches and fade through the terrain's `fringe` (`terrain.ts`); `habitat` on a terrain lists the climate it needs. `fit.ts`: `terrainIssues` (wrong climate, painted over sea), `siteIssues` (needs: coast/river/water/flat/arable/highland, big cities need the sea or a 6+ km river), `snapToCoast`, `fitTerrain`, `fitSite`. `validate` warns for all of it; CLI `fit <file> terrain|site <id>` and `sites <file>`; `brief` explains the rules. Close-up relief is damped on lowlands (`fine` in `relief`) so plains are flat at village scale.
  - When building or editing a world: find spots with `fit`, then `validate` and `sites` until there are no warnings (except deliberate magic).
- Ideas beyond the plan: CLI command to add layer items, scene location pins, antimeridian-safe polygon fills, more terrain types as the user describes them (add to `terrains.ts` plus a showcase region).

Gotchas:
- To drive the Globe in a hidden pane, call `cancelAnimationFrame(globe.raf); globe.loop()` in a timer (a bare `globe.loop()` leaks one rAF chain per call and freezes the page), then poll `globe.queue.length`; tiles load slowly there.
- The preview pane runs requestAnimationFrame only while visible; when hidden, frames advance only on screenshots, so take a few screenshots before judging tile loading.
- In dev, `window.globe` is the live `Globe` instance (set after `setWorld`). Fly with `globe.flyTo(lat, lon, dist)`, where dist is in planet radii (3 = orbit, 0.004 = near the ground).
- Keep `src/world/*.ts` pure (no DOM, `.ts` import extensions) so node tests and the CLI can run them.
- `setWorld` ignores name/note/wikiId changes, so renames don't rebuild tiles. Keep it that way for layer item labels too.
- Settlement shaders read the same `iPos/iUp/iA` frame as props (yaw measured against the shader's own tangent frame, fixed up in `buildSite`); changing a prop attribute layout means changing `settleMat` too. Decals sit 3.5 m above the ground and instances stand on `g.h`; the log depth buffer ignores polygonOffset, so lift geometry instead.

## New Map Test (flat worlds)

A separate section (`/map-test`, `src/flatworld/`) that leaves the Globe alone. A flat world is a rectangle or a disc (`shape`, `size` in km, x east / y north from the centre) plus named `features` (land, sea, range, peak, volcano, hills, plateau, canyon, river, lake, painted biomes; Claude writes these) and `layers` (cities, landmarks, regions, borders, roads; the user draws these). Stored as `book.flatWorlds`, synced as `flatworlds/<id>.json`.
- `gen.ts` (pure): `validate`, `generate`, `wallMesh`, `treesOf` (far + near lattices), `brief`. Pipeline: coasts (shared domain warp; coast kinds mixed/beach/cliff/fjord/mangrove) -> plains -> ranges/peaks/hills -> `erode` (stream power + talus at half resolution) -> plateaus, volcanoes, canyons, craters, sinkholes -> optional `climate` biomes (warmth by latitude and height; rain swept along the wind, blurred, with rain shadows) -> biome shaping (dunes, terraces, salt flats, ice, lava cracks) -> lakes at their own level -> rivers (lowland meanders, stepped falls, tributaries, deltas) -> colours. Outputs `height`, `rgba` (alpha = lava), `data` (water depth, lake mask, FX code, ambient), `rough` (close-up detail), lakes, falls, props (floating, gianttree, arch), zones (magic/storm/blizzard points), whirls, summits. `exagOf` = size / 120. `detailAt` is integer-hash noise duplicated exactly in GLSL; `surfaceAt` = height + detail, so markers sit on the drawn ground. The worker gets the world with names, notes and layers stripped, so renames and layer edits never rebuild terrain.
- `scene.ts`: ground drawn on the GPU in quadtree tiles (64x64 grid with skirts, depth 9) from a float height texture plus `detailN`; heights ease from full exaggeration far away to 40% up close (`uHScale`) and everything on the ground follows. Shadows: a half-res pass ray-marches the height grid toward the sun, redone when light or scale changes. Lights day / golden / night / cycle (`SUNS`); styles toon / watercolour / atlas / neon (final pass). Also water (see-through shallows, depth contours, reefs, whirlpools, lake planes), river ribbons with white water, 13 tree kinds (far + near buckets), particles (smoke, summit snow, spray, motes, rain, snow), props, ships, birds, storms with lightning, edge waterfall. `MapControls`; Q/E turn; `proj`/`ground`/`flyTo`/`north`/`footprint`/`snapshot` for the page.
- `route.ts` (pure): `route` = least-cost path on a third-resolution grid where rivers / ridges / coasts are cheap (Follow: free, rivers & ridges, rivers, ridges, coasts; corridor-limited), `fillRegion` = flood fill over land stopped by the sea, borders (loose ends joined to the nearest sea within 150 km) and other regions, traced back to an outline. Items with `curve: true` are drawn through a Catmull-Rom curve (`itemShape` in gen.ts, used for drawing, fills, picking and stats). Region outlines are not drawn over the sea.
- `hud.ts`: screen-space 2D layer each frame (borders, roads, region outlines, city/landmark icons, labels with curved text on rivers/ranges, ruler, drafts, handles) and the hit list for picking. `dress.ts`: compass rose, scale bar, legend, parchment frame for PNG export.
- `MapTestPage.tsx`: tools (select/drag, city, landmark, region, fill, border, road, ruler; snapping; each click-to-click leg routed by the Follow mode with a live preview; Curved toggle), popups (rename, notes, size/icon, zoom to, delete), layers panel, search, minimap, undo/redo (Ctrl+Z/Y), Export/Import JSON, "For Claude" (copies brief + JSON), PNG.
- Earth-real paint kinds added for Eyaris: `karst` (tower forest, shape `towers`), `geothermal` (mineral crusts, steam from `Gen.steam`), `lavafield`, `floodplain` (shape `smooth`: levels the ground along big rivers).
- `examples/eyaris.json`: the user's main world, Earth-like extremes, no fantasy features. It was 13000 x 7500 km, centred on the map; on 2026-11-06 it grew to 39000 x 19483 km (nearly the whole planet at Earth size) with new continents, ice lands and island chains around it, so land covers about 25% of the globe. Old coasts stay exactly in place because `warpSize` (13000), `relief` (0.15, size x relief unchanged), `climate.bands` (the old warmth, then cooling again to the far south) and the same km per sample (`resOf` in `built.ts`) are all fixed; the map must keep that cell size and even grid offsets. Keep new land a few hundred km of sea away from the old land, or rain changes. The main continent stays the largest (26.7M km² on the sphere, next is 19.4M) and Dematrus the highest. Only "Dematrus Mountains" and the city "Stones Hold" are named on purpose; the user names the rest later, so "give it a name" warnings are expected. Seas must come after all land in `features` (a later land fills a sea back in). A full build takes about 30 s in the browser, once per session.
- CLI: `node scripts/map.ts brief|describe|validate|preview|add <file>`. Test fixtures (no longer loaded by the app): `examples/map-test-demo.json` (rect, climate, every feature) and `examples/map-test-disc.json` (disc, waterfall edge).
- Effects (smoke, clouds, ships, birds) stay sized as on a 13000 km map on a bigger one (`FX_KM`); the Smoke checkbox hides volcano smoke. In dev, `window.mapScene` is the live scene. The preview pane runs the generator ~7x slower than node; drive tools there with dispatched pointer events (screenshot and click coordinates differ).
- Gotchas: in the dev console the page's store is the module URL with its `?t=` stamp (see performance resource entries); a bare `/src/store.ts` import is a different, stale instance. Tile triangles must wind counter-clockwise seen from above (world z = -north) or the land is culled; the coast ink uses the smooth height (`vH0`), not the detailed one, or all land gets inked from far away.
- Globe tab (`/globe`, `GlobePage.tsx`, `globeScene.ts`, pure `sphere.ts`): Eyaris on a sphere, view only, saves nothing. True size: an Earth-radius planet (6371 km; `planetKm` grows it only for maps too big to fit) with the map centred on the equator by `toSphere`: rectangles are plate carree (x = longitude, y = latitude, so north-south stays true and east-west shrinks by cos(latitude); a 39000 x 19483 map covers nearly the whole sphere), discs azimuthal equidistant (they stay round). Anything left over is open ocean. Quadtree tiles (`updateTiles`, skipping those over the horizon) on an ocean sphere, reusing `COMMON`/`uniforms` from `scene.ts`: same colours, heights and toon light as the flat map, rivers from a canvas mask. No trees, shadows, clouds, labels or layers. Heights use `g.exag`, easing to 40% near the ground like the flat map. Camera: `OrbitControls` drives `rig` (straight above the ground, up = the planet's axis, so drags turn around that axis); `camera` leans back from the same focus point near the ground and rolls so the orbit is level from space and north is up near the ground; speeds scale with altitude; frames are drawn only when something moves. `built.ts` holds the worker build, cache and `specOf`, shared with the Map tab so neither rebuilds, and `mainWorld`: the Globe always shows Eyaris (id `eyaris`) and the Map opens on it; other worlds only come up if the book has no Eyaris. In dev, `window.globeScene` is the live scene. Up close the land is as sharp as the height grid (about 8.5 km a cell on Eyaris), which is why zoom stops a few hundred km up.
- Solar system on the Globe tab: `solar.ts` (pure tables and maths: `TILT_DEG`, `YEAR_DAYS`, `MOONS`, `PLANETS`, `CONSTELLATIONS`, each with room for a `name`; nothing is saved in the book, and nothing there is named yet because the user names things) and `solarScene.ts` (`SolarSky`: `scene`/`camera` are the far sky drawn first with no parallax, 1 AU = 1000 units, stars, galaxy band, constellations, sun, planets, belt; `system` joins the planet's scene in planet radii: axis marker, tilt arc, moons and their orbits). Eyaris stays at the origin in a fixed frame whose xz plane is the orbit; `planet` is the group that leans (`lean`) and turns (`spin`), and land and sea shade in its own frame (`uSunP`, `uCamP`, GLSL `SPACE`). Planets are drawn bigger than life (`apparentDeg`); `START_DAY` and the orbit phases are chosen so the opening view shows the sun, the ringed giant and the broken world.
  Normal view: time stands still and `uReal` = 0, the evenly lit map. Cinematic (`GlobeScene.set`): `tick` runs the clock and eases `uReal` to 1: real terminator, dusk, sun glint, seasons (`uSeason` 1 at northern midsummer; ground uses `Gen.warm`: winter snow, summer thaw, autumn leaves; sea ice by latitude). `aim` keeps the camera with the sun and swings it between a lit face and a crescent, and gives way for 9 s when the viewer drags (`grabbed`). A year is 24 days on screen, sped up, not the story's calendar. The preview's hidden pane resizes the canvas by a few pixels on screenshots, which can catch a blank frame.
- Not yet: wiki/timeline/scene links and party route (planned later).

## Timeline page

`/timeline` has two parts. **Production Timeline** (`TimelinePage.tsx`, `timelineScale.ts`): dated events and periods on a rail; new items start on the selected event's day; the wheel is not hijacked so the page scrolls on to the plan. **Planning Timeline** (`PlanTimeline.tsx`, pure helpers in `plan.ts`): `book.plan` is a dateless ordered list (array order = order; synced as `plan/<id>.json` plus `planOrder` in `book.json`); drag to reorder, + between cards inserts, arrows for touch, "Move to Production Timeline" turns a card into an event. `merge.ts` merges events, periods, plan items and threads field by field when both devices edit one (`FIELDWISE`); only chapters, scenes, wiki and ideas still save an "(other device)" copy.

## Locations (city-scale 3D places)

`/locations`, `src/locations/`. The end goal is MASSIVE cityscapes, above all **Stones Hold** (the main city: a mountain range turned into a city across valleys and peaks; the higher, the wealthier, with slums in the valleys; glacial lakes, aqueducts everywhere, enormous peak-to-peak bridges, rival families' competing cathedrals (Cologne, Sagrada Familia), statues and plazas everywhere, a St Peter's style colonnade). Detail goes into the megastructures and the atmosphere, not into every house. Desktop only (no phone compromises), no interiors, no walking view; flying matters. Not on the Map or Globe for now. The user wants the system able to build anything they describe, realistically: everything has a reason (natural processes, town logic) and is checked, never random circles.
- A location is a recipe Claude writes (`LocationDoc` in `city.ts`); `node scripts/loc.ts brief` prints the full format (every landform, town and structure field). Recipe coords are metres, x east, y north; world is x, z = -y. Climates: temperate, alpine, mediterranean, arid, tropical, boreal (they set snow line, tree line, palette, trees).
- `terrain.ts` (pure): landforms compiled once into closures with bounding boxes (`terrainOf`; later features win; coasts/fjords after the land they cut). Kinds: peak/island (warped radius; glacial ones, over ~1100 m of relief, get cirques: bowls under rock headwalls, leaving aretes and horns), ridge (summits and cols along the crest, cirques on the shaded flank), valley (`height` to `end`, axis winds in bends of ~6 widths, `meander`), coast (shore = path offset by hard/soft rock: headlands with cliffs, wave-cut platform, stacks and an arch; bays with beaches; the sea side closes far away, tested by a cached point-in-polygon), fjord, cliff (escarpment: spurs, talus), gorge, canyon (stepped), mesa, plateau, glacier (routes itself along the valley between its waypoints with `routeLine`, plans a gently falling bed, U-trough, moraine banks; ends at `height`), volcano (concave cone, barrancos, crater or caldera, parasitic cones; `active`), crater, dunes, geyser mound, rock kinds (stack, arch, spire, karst towers, hoodoos, basalt columns -> `T.rocks`). Every steep face is also a `Wall` line. `pathNearFast` answers nearest-point queries on long lines from a raster of nearest segments (two sweeps) plus a local walk; `setLineRegion` bounds those rasters.
- `hydro.ts` (pure, on the grid): `fluvial` stream-power erosion at half res (priority flood order, implicit incision, talus; pits under 10 m filled; `hard` cells (cliffs) incise with the land but never slump, so cliffs are worn back instead of being left standing as walls), `drySeaPuddles`, `makeLake` (level found by area so the shore is a contour; specks sunk, moraine dam where it would spill), `routeRiver`/`routeLine` (A* that keeps to valley floors), `meanderRiver` (sine-generated loops where flat, ~11 widths), `carveRiver` (never uphill; the level is the lowest ground across channel and banks, so water never stands above a bank; the banks widen with the depth of the cut, ~20 degree valley sides instead of a trench; falls into pools, estuary funnel drowned to sea level), `carveDelta` (lobed plain + distributaries). `Heap` is a typed binary heap (`key` = last popped key, skip stale entries).
- `town.ts` (pure, world coords): `growTown` = Dijkstra from the core over slope/water cost until pi r^2 (shape follows valleys, shores, contours; `zone` 0 core .. 1 edge, `farm` = how far its fields reach, `inside` signed distance); `townStreets` = tensor field (along main roads, radial round the square, contours on slopes) traced as major/minor streamlines a block apart, dangling ends joined, steep minor stretches become stairs; `zoneOutline` (marching squares) gives the wall line. `withTownCentres` (city.ts) adds a `market` square and a parish `church` per town unless taken; sea towns get a `harbour` automatically.
- `city.ts` `buildCity` order: ground (`T.h`) -> dry sea puddles -> towns grow -> erosion mask -> `fluvial` -> lakes -> rivers (+ deltas) -> droplet `erode` -> relief sharpening on steep ground -> living ground (lava flows from active vents, lava fields, springs terraces + pools, geysers, marshes; `marks` texture R lava / G mineral / B wet; `steam` vents) -> wealth -> main roads (hubs: squares, great buildings, bridges, harbours) -> each town's streets, walls -> carve -> canals -> occupancy -> houses (`placeAll`: attached rows in the core, gaps and front gardens toward the edge, block interiors left as yards) -> gardens, square trees -> farmland (`parcels`: Voronoi patchwork, strips for central; whole parcels farmed; per-culture `CROPS_OF`; vines/orchards/hedges/walls/farmsteads) -> field texture (~7 m) -> AO (horizon, baked into colours) -> colours (cleared meadows near towns, forest where `forestP`, alpine meadows, rock above ~40 degrees, glacier snow/ice/moraines, beaches, tidal flats, wetland) -> trees -> outer backdrop -> structures, rock faces (`rockWalls` sampled on the drawn triangles, grid sunk behind, `cliffMask` keeps coarse LODs behind the rock), rock forms, roads (kerbs, lamps, retaining walls and parapets on slopes), bridges, canals -> water (lake cells, pools, river ribbons not drawn where the sea or a lake takes over) -> `audit`. `stages` times each step (showcase: ~25 s node, ~50 s in the preview pane; cached in IndexedDB). Bump `BUILD_VERSION` when the output changes.
- `check.ts` `audit`: terrain needles, uncovered vertical steps, dead-flat area, stranded sea, rivers with banks below the water, lake roundness, glacier ice above its banks, town roundness, street density and dead ends, houses off streets, main road grades. `node scripts/loc.ts check <file>` prints it; `built.audit` carries it.
- `buildings.ts` (pure): houses are lists of parts (`PSTRIDE` 17 floats), drawn instanced per `PART` (20 kinds). `design(culture, wealth)` per culture; `placeAll` uses each town's `zone`.
- `roads.ts` (pure): main roads by A* (grade over 0.3 impassable, dear above 0.06, capped at 0.15 after smoothing); kinds main/street/lane/stairs; `RoadIndex`; `carve`.
- Detail hierarchy: `Builder.tiers` (`TIERS` in kit.ts): 0 massing (always), 1 ornament (pinnacles, parapets, voussoirs, statues, lamps; drawn within 2.6 km), 2 carving (crockets, tracery, balusters, jamb figures, gargoyles, corbels; within 800 m). Kits put detail on finer tiers with `b.fine(t, fn)`; `CityBuilt.detail` carries tiers 1..2 and `scene.ts` draws them in 500 / 250 m chunks with LODs (`DETAIL_LOD`). Houses and terrain stay tier 0 on purpose: the detail goes into the great structures. Small places are sharper on their own: `gridN` aims at size/1000 m cells (1.5..12 m) and `texN` at 1.5..7 m texels.
- Variation: `cathedral` picks from its seed six to eight bays, spires (solid with crockets, openwork over an octagonal belfry, lantern, or flat-topped towers with tall pinnacles), a transept with rose fronts, a flèche / lantern tower / tower and spire over the crossing, a chevet of radiating chapels, roof metal; the west front has three portals with jamb figures, a gallery of kings, the rose, an arcaded gallery. `arcade` styles (`style` on bridges/aqueducts, default from the seed): bridges roman, gothic (pointed arches, cutwaters rising to refuges, gate towers, a mid-stream tower on long ones), renaissance (segmental arches, spandrel oculi, half-moon refuges, balustrade, statues), inhabited (houses on brackets); aqueducts roman (Pont du Gard: small arches on top carrying the covered channel, masons' blocks), segovia (stepped piers, impost courses), moorish (striped horseshoe arches). Piers standing in water (`wet`) get cutwaters; street bridges over rivers are `plain`.
- Backdrop: only a fringe of `margin` (0.35 x size, 2.5..9 km) round the place, where the land settles to lowland (sea stays sea); `skirtMesh` carries the rim out flat to 250 km for the haze, and the sea plane is as big.
- `kit.ts` (pure): `Builder` and kits (cathedral, basilica, colonnade, domeChurch, palace, monastery, arcade, cityWall, harbour, tower, plaza, statue, `church` per culture, `market` with fountain and stalls). Materials include `rock` (natural rock shader). New kits: `STRUCTURE_KINDS`, `footprint` (terrain.ts), `structure()`, `brief`.
- `rock.ts` (pure): `rockWalls` (faces that follow the ground's own profile across each wall, buttresses, bedding ledges, tide band; short gaps bridged), `rockForms` (stacks, arches, spires, karst towers, hoodoos, hexagonal columns), `sheet` (smooth-shaded grid).
- Renderer: `scene.ts` (terrain tiles with 4 LODs; merged meshes split into 1400 m chunks; field and marks textures; lava glow as terrain emissive; `shots(prefix, list)` and `shot(name)` in dev save JPEGs to `test/out/shots/` through the `/__shot` dev middleware in `vite.config.ts`), `shaders.ts` (`ROCK`, field texture, marks, terrain AO is baked, strata softened), `fx.ts` (cumulus clusters with flat bases, count by weather; mist puffs only in real mist; steam vents: spring wisps, geyser columns, volcanic plumes), `water.ts`, `fly.ts`.
- `LocationsPage.tsx`: the picker lists the book's locations plus bundled demos (`examples/showcase.json`: glacier to sea; `examples/active-lands.json`: volcanic tropical coast), demos are only saved into the book when changed.
- Claude's loop: write/edit the JSON; `node scripts/loc.ts validate|describe|check|preview <file>`; `node scripts/loc-time.ts <file>` for stage timings; fix warnings; then in the browser pane `await locScene.shots('x-', [[name, [x, y, alt], heading, pitch], ...])` (negative alt = metres above ground) and Read the JPEGs. The preview pane runs rAF only while visible; `shots` draws its own frames.
- Not yet: Stones Hold itself (reference images coming); the showcase river still has many small falls (the running-minimum profile) and its water stands above a bank in the steep gorge and at its source (the routing grid is coarser than the gorge floor); the glacier tongue stands above its banks in places (audit 18%); 1% of the land is steep ground without a rock face; a cold/arid demo (fjords, mesas, canyons, dunes are built but not in a demo); quays along town shores; parallel ground build; bloom; sync merges a location edited on two devices by keeping an "(other device)" copy.

## Writing room

The user writes mostly in **Scenes**, not Write, and works alone: new writing features go to Scenes first, then Write. Both use the same room (`Room.tsx`: top bar, Aa settings, goal, focus, side panel; `useWriter` holds its state) around the same editor (`prose.tsx`: `useProse`, `Toolbar`, comment mark, autofill). Pure logic has no runtime imports and is tested in `test/writing.test.ts`: `text.ts`, `comments.ts`, `connect.ts`, `replace.ts`, `claude.ts`, `autofill.ts`. `store.ts` touches IndexedDB on import, so pure code imports from `text.ts`, never the store.

- Scenes: `/scenes?s=id` opens the room (the id lives in the address so Back and links work). Words typed count through `addWords`; `snapshot` works per scene. Book totals use `bookWords` (placed scenes are in their chapter, loose scenes count too). Today's Continue uses `room-last`.
- Scene order never depends on dates, which are optional: early scenes usually have none. The board shows `sceneOrder`. Dragging a card up or down calls `moveScene` (Earlier/Later in Details does the same for touch): array order for loose scenes, and placed scenes also move their block in the chapter text. Scenes only reorder within their group (`canReorder`): a drag never moves a scene into or between chapters, that is the Chapter field. Dragging to another column changes the stage as before.
- Side panel: Story (`sceneNeighbours`, summaries always visible, full text on request, order from `sceneOrder`: chapters, then the board), Details, Comments, Links, Find.
- Comments are private notes to self. They have no data of their own: a mark `<span data-comment=id data-note=URI-encoded>` in the prose, so sync, merge and the scene/chapter mirror just work and exports drop them. Clearing removes the mark; undo brings it back.
- Connections (`connect.ts`, shown by `Connected.tsx` on every item page): worked out from scene fields, dates, and names in text (case-sensitive, so Rose is not "she rose"). A map place and a wiki page with the same name are one thing and share connections. The only link kept by hand is `TEvent.sceneIds`. The graph is cached per version of the book (WeakMap).
- Autofill: faint inline text (`complete`), wiki names and aliases only, exact case, 3+ letters, skips common sentence starters. Tab or a tap takes it, Esc hides it, typing past ignores it. No menu: the old menu was removed because it got in the way. Nothing shows while a phone keyboard is composing.
- For Claude (`claudeBrief`): copies text, neighbours, wiki entries, events and comments for continuity checks and feedback. Claude must not write the user's prose. No AI inside the app.
- Find (`Find.tsx`, `replace.ts`; Search page and the panel, Ctrl+H in the room): searches text between tags only, so notes and ids are safe. Placed scenes count once, under the scene. Replace shows every match with a checkbox, snapshots first, has Undo, and can keep an old wiki name as an alias. Limit: one text run at a time, so a word half in italics or half under a comment is not found.
- Links with `?find=text&n=2` land on a match; `/map-test?w=&place=` flies to a place and opens it; `/ideas?i=`, `/timeline?e=`, `/timeline?p=`.
- Not yet: Insights' character grid still reads chapters only (Scenes' Lanes view covers scenes). Autofill on a phone keyboard (composition hides it).

## UI conventions
Neutral dark grey theme (light "Mist" is neutral too), navy accent, no background art. Every page opens with `PageHead` (`src/ui.tsx`: title left, actions right, one-line hint); `useLocal`/`readLocal` keep small per-device preferences in localStorage (editor font/size/width/typewriter `write-prefs`, chapter list `write-list`, last chapter `write-last`, nav groups `nav-closed`, timeline `tl-zoom`). `/today` is the landing page (continue card, goal, next step from `next.ts`, idea capture, getting-started checklist). Write has a chapter column beside the editor (a floating panel under 900 px), Aa editor settings, a goal bar and a save-state label. Wiki has type filter chips, avatars and a card overview. Timeline has an overview strip, zoom (View menu) and accepts dropped planning cards.
